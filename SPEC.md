# PD — спецификация приложения для падела

Oct 18, 2026 · @Pavel · версия 2

## Обзор

PD — мобильное веб-приложение для компании друзей, которая играет в падел: оно строит очерёдность игр на одном или нескольких кортах и ведёт турнирную таблицу в течение одной игровой сессии.

Название — **Padel Dashboard** (аббревиатура PD, по традиции автора). Репозиторий — `padel-dashboard`, адрес — `pdmulenko.github.io/padel-dashboard/`.

Ключевые сценарии:

- Американо: личный зачёт, пары меняются каждый тур, число игроков любое от 4 (не обязательно кратно 4).
- Фиксированные пары: командный зачёт; ротация «по кругу» или (только на одном корте) «победитель остаётся».
- Один или несколько кортов одновременно; на нескольких кортах игра идёт общими турами.
- Счёт матча — два произвольных числа (2:1, 6:4, 24:18 — на усмотрение игроков). Опционально можно задать фиксированную сумму очков за матч, тогда вводится одно число.

Один телефон с открытым приложением, который передают из рук в руки или держит один «судья». Мультиустройственной синхронизации нет.

## Стек и хостинг

Чистый HTML + CSS + JavaScript без фреймворков и сборки; хостинг на GitHub Pages из отдельного публичного репозитория.

- Структура: `index.html`, `style.css`, JS-модули (`<script type="module">`): `state.js` (модель и хранение), `scheduler.js` (алгоритмы расписания), `scoring.js` (подсчёт и таблица), `i18n.js` (тексты интерфейса), `ui.js` (рендер и события).
- Логику расписания и подсчёта держать чистыми функциями без DOM. Источник случайности передаётся в функции расписания параметром (генератор с seed), чтобы тесты были воспроизводимыми.
- Тесты — в папке `tests/`, запуск встроенным раннером Node: `node --test`. Минимальный `package.json` (только `"type": "module"` и скрипт `test`), без зависимостей.
- Состояние — в `localStorage` (одна запись с JSON всей сессии), сохранять после каждого изменения.
- Без внешних зависимостей и CDN: приложение должно работать и при плохом интернете на корте.
- Все пути (в HTML, `manifest.json`, service worker) — относительные, потому что сайт живёт в подпапке `/padel-dashboard/`.
- Локальный запуск: JS-модули не работают при открытии `index.html` двойным кликом, поэтому для разработки — простой сервер, например `python3 -m http.server` в папке проекта.
- Иконки кнопок — Font Awesome Free (solid), но не через CDN: нужные иконки лежат локальным SVG-спрайтом `icons.svg` (как в PrettyDrafter) и подключаются через `<svg><use href="icons.svg#fa-…"/></svg>`; строка лицензии Font Awesome сохраняется в спрайте.
- Favicon и иконки приложения — монограмма «Pd» с сайта pdmulenko.github.io (папка `icons/`).
- Желательно: `manifest.json` и иконка, чтобы можно было «Добавить на экран Домой» и открывать как приложение (PWA с service worker — опционально, вторым этапом).

## Настройка сессии

При первом входе (или по кнопке «Новая сессия») пользователь за один экран задаёт режим, корты, подсчёт и участников.

| Параметр | Значения | По умолчанию |
| --- | --- | --- |
| Режим | Американо / Фиксированные пары | Американо |
| Ротация пар (только фикс. пары) | По кругу / Победитель остаётся (только при 1 корте) | По кругу |
| Число кортов | от 1 до ⌊игроков / 4⌋ (для пар — ⌊пар / 2⌋) | 1 |
| Сумма очков за матч | выкл. / число (быстрый выбор 19, 25, 31, 32) | выкл. |
| Конец игры (только американо) | Свободный / По числу туров / По числу кругов | Свободный |
| Число туров / кругов | число | туров — по числу игроков, кругов — 1 |
| Максимум матчей подряд (только «победитель остаётся») | число / выкл. | 3 |
| Игроки | список ников, минимум 4 | — |

- Ники: уникальные, непустые, обрезать пробелы; удобный ввод по одному с кнопкой «+» и удалением.
- В режиме фиксированных пар игроков объединяют в пары: вручную (выбор напарника) или кнопкой «Случайно». Нужно чётное число игроков и минимум 2 пары; при нечётном числе — понятное сообщение.
- Если игроков (пар) не хватает на все корты, приложение использует столько кортов, сколько возможно, и показывает об этом подсказку.
- Число кортов можно менять между турами.
- Приложение запоминает ники прошлой сессии и предлагает их одним тапом («Те же, что в прошлый раз»).
- Порядок игроков случайно перемешивается при старте, чтобы первый тур не зависел от порядка ввода.

### Конец игры (американо)

- **Свободный:** турнир идёт, пока его не завершат вручную.
- **По числу туров:** после N-го тура турнир завершается сам.
- **По числу кругов:** круг — каждый хотя бы раз побывал в паре с каждым. Число туров считается как ⌈круги · n·(n−1)/2 ÷ (2 пары напарников × корты)⌉ и округляется вверх до момента, когда у всех поровну матчей (например, 8 игроков: 1 корт — 14 туров, 2 корта — 7). Пересчитывается при смене состава.
- Во время игры заголовок «Тур k из N»; в последнем туре прогноза нет, вместо него пометка «последний тур».
- После завершения вкладка «Игра» исчезает, вкладка «Итоги» открывается сама и показывает сверху «Турнир завершён! Победитель: …» (при равенстве разницы и забитых — несколько победителей); под таблицей — кнопка «Отменить последний результат».

## Режимы и алгоритмы расписания

Тур — это матчи на всех используемых кортах одновременно: на каждом корте играют 4 человека (2 пары), остальные отдыхают. Следующий тур начинается, когда введены результаты всех матчей текущего тура.

Для режимов «американо» и «по кругу» следующий тур вычисляется заранее (он не зависит от счёта) и фиксируется: именно он показывается в блоке «Следующими играют» и именно он будет сыгран. Пересчитывается он только при изменении состава, числа кортов или при «Отменить». Для «победитель остаётся» следующий матч определяется только после ввода результата текущего.

### Американо

Обозначения: m — число кортов в туре, в туре играют 4m игроков.

1. Выбор игроков тура: сначала обязательно все, у кого меньше всего матчей. Среди игроков с одинаковым числом матчей выбирается тот состав, который даёт наименьший штраф (см. п. 2), причём учитывается и следующий тур, если его состав уже предопределён; при равном штрафе — предпочтение тем, кто дольше на скамейке, затем случайно. (Жёсткое правило «сначала дольше на скамейке» не годится: при 8 игроках одни и те же четвёрки играли бы вместе всю сессию.)
2. Разбивка на пары и корты: штраф варианта = сумма по всем матчам тура: 10 × (сколько раз эти напарники уже играли вместе) + 1 × (сколько раз эти соперники уже встречались). Берётся вариант с минимальным штрафом, при равенстве — случайный. На одном корте у четвёрки ровно 3 варианта ({AB–CD}, {AC–BD}, {AD–BC}); при 2 кортах полный перебор (315 вариантов) приемлем; при 3+ кортах допустим жадный подбор.
3. Свойство, которое нужно сохранить: среди игроков, присутствующих с начала сессии, разница в числе матчей никогда не превышает 1. Все сыграли поровну через n / НОД(n, 4m) туров (n — число игроков): например, на одном корте при 6 игроках — каждые 3 тура, при 8 — каждые 2, при 9 — каждые 9.
4. Опоздавший игрок стартует с 0 матчей, поэтому по правилу п. 1 он будет играть несколько туров подряд, пока не догонит остальных. Это ожидаемое поведение.
5. Приложение показывает подсказку «до равного числа игр: N туров» (N — минимальное число туров, после которого у всех активных игроков поровну; вычисляется прогоном того же правила выбора на копии состояния; при N = 0 — «все сыграли поровну»).

### Фиксированные пары — по кругу

1. Цикл = все сочетания пар друг с другом (k пар → k·(k−1)/2 матчей).
2. Каждый тур выбирает до m непересекающихся (без общих пар) матчей из ещё не сыгранных в текущем цикле: приоритет парам с наименьшим числом матчей, затем тем, кто дольше отдыхал; на одном корте — избегать третьего матча подряд для одной пары, если есть альтернатива.
3. Когда цикл закончен, начинается новый. При 2 парах всегда играет один и тот же матч.

### Фиксированные пары — победитель остаётся (только 1 корт)

1. На корте две пары, остальные стоят в очереди в порядке ожидания.
2. Победитель остаётся, проигравший уходит в конец очереди, на корт выходит первая пара из очереди.
3. Настройка «максимум матчей подряд» (по умолчанию 3, можно выключить): достигнув лимита, пара уходит в конец очереди даже после победы, а в следующем матче выходят две первые пары очереди.
4. Ничья: уходит пара, которая дольше находилась на корте. Если обе вышли на корт одновременно, уходит та, что стояла в очереди дальше (вышла второй).
5. При 2 парах всегда играет один и тот же матч.

### Общее для всех режимов

- Перед началом тура можно вручную заменить участника («у меня перерыв»): в американо — отдельного игрока, в режиме пар — только пару целиком. Заменённый не теряет приоритета на следующий тур.
- Если из-за выбывших активных игроков стало меньше 4 (в режиме пар — меньше 2 пар), приложение показывает понятное сообщение и предлагает вернуть кого-то или добавить игроков, а не ломается.

## Ввод результатов и таблица

Ввод счёта должен занимать пару тапов потными руками на корте: крупные кнопки, без клавиатуры там, где можно.

### Ввод

- Счёт матча — два целых неотрицательных числа, по одному на пару. Ввод — крупными степперами «−»/«+» для каждой пары (быстрый ввод через клавиатуру тоже доступен).
- Если задана сумма очков S: пользователь выбирает очки одной пары (сетка кнопок 0…S), очки второй считаются автоматически как S − x.
- Ничья допустима.
- При нескольких кортах счёт вводится по каждому корту отдельно; кнопка «Сохранить» у каждого матча. Когда сохранены все матчи тура, сразу показывается следующий тур.

### Таблица

Одна схема для всех режимов; в американо строки — игроки, в режиме пар — пары.

| Колонка | Содержание |
| --- | --- |
| Игрок / Пара | ник или «ник + ник» |
| Матчи | число сыгранных матчей |
| В-Н-П | выигрыши, ничьи, поражения; числа разными цветами: зелёный, нейтральный (цвет основного текста), красный — с достаточным контрастом в обеих темах |
| Забито | сумма очков своей пары во всех матчах |
| Пропущено | сумма очков соперников |
| Разница | Забито − Пропущено; главная колонка, выделена визуально |

- Сортировка: разница ↓, затем забито ↓, затем по нику.
- В американо каждый игрок получает в личный зачёт счёт своей пары.
- Если число сыгранных матчей у игроков сейчас не равно, это видно по колонке «Матчи», а над таблицей висит подсказка «до равного числа игр: N туров».
- История матчей: список всех сыгранных туров (номер тура, корт, составы, счёт), новые сверху.

## Управление сессией и хранение

Сессия переживает закрытие вкладки, перезагрузку и смену состава по ходу игры.

- **Опоздавший игрок (американо):** добавляется в любой момент; стартует с 0 матчей и играет подряд, пока не догонит остальных (см. алгоритм).
- **Ушедший игрок:** помечается «выбыл» (не удаляется), его результаты остаются в таблице, в расписание он больше не попадает. Можно вернуть.
- **Фиксированные пары:** добавление и снятие целой пары по тем же правилам; для «по кругу» цикл пересчитывается.
- **Исправление счёта:** любой сыгранный матч можно открыть из истории и поправить счёт; таблица пересчитывается. Составы уже сыгранных матчей не меняются.
- **Отмена последнего действия:** кнопка «Отменить» для последнего сохранённого результата (матч снова становится текущим, заранее вычисленный следующий тур отбрасывается).
- **Таблица — всегда производная:** хранится только список игроков/пар, настройки и история матчей; статистика каждый раз вычисляется из истории. Так правки и отмены не ломают данные.
- **Хранение:** одна запись в `localStorage` с полем `version` для будущих миграций; при битых данных — предложить начать заново, не падать.
- **Новый турнир тем же составом:** с подтверждением; сразу начинает новый турнир с теми же активными участниками и настройками, порядок перемешивается заново.
- **Завершить турнир:** с подтверждением; стирает турнир и возвращает на стартовый экран. Ники сохраняются для кнопки «Те же, что в прошлый раз».
- **Поделиться итогами:** кнопка, которая копирует итоговую таблицу текстом (или через Web Share API) для отправки в чат компании.

## Экраны и UI

Стартовый экран и три вкладки во время игры; одна вертикальная колонка шириной до \~30rem; на десктопе та же колонка по центру.

1. **Стартовый экран:** сверху переключатели темы и языка (как на pdmulenko.github.io: «☀ Светлая ⬤ Тёмная ☾» и «🇷🇺 Русский ⬤ English 🇬🇧»), ниже параметры из раздела «Настройка сессии», список ников, кнопка «Начать».
2. **Игра:** сверху текущий тур крупно (тур №, для каждого корта: две пары в тонких рамках со скруглёнными углами, между ними крупное жирное «vs», внутри пары крупный «+»; ввод счёта и «Сохранить»); ниже «Отдыхают», затем «Следующими играют» (кроме режима «победитель остаётся», там — «Очередь»). Таблицы на этой вкладке нет.
3. **Итоги:** баннер о завершении (если турнир завершён), полная таблица с подсказкой про равное число игр, кнопки «Отменить последний результат» (только после завершения), «Поделиться итогами», «Новый турнир тем же составом», «Завершить турнир», ниже история матчей с правкой.
4. **Настройки:** логотип и название «Padel Dashboard» (во время игры шапки нет, чтобы не занимать место — сверху сразу вкладки), переключатели темы и языка, «Игроки и корты» (число кортов, добавить/снять игрока или пару).

Требования к интерфейсу:

- **Никаких `px` в CSS:** только относительные единицы (`rem`, `em`, `ex`, `%`, `vw`/`vh`/`dvh`, `ch`), в том числе для рамок и медиазапросов. Ориентиры: зона тапа не меньше 2.75rem × 2.75rem (≈ 44 px), колонка до 30rem.
- Крупный шрифт для счёта, хороший контраст на солнце.
- Светлая и тёмная тема: по умолчанию по `prefers-color-scheme`, переключатель задаёт тему вручную и запоминается.
- Сетка выбора очков (при заданной сумме S) — прямоугольник, близкий к квадрату: ⌈√(S+1)⌉ столбцов, крупные кнопки; над сеткой подпись, чьи это очки.
- Учитывать безопасные зоны iPhone (`viewport-fit=cover`, `env(safe-area-inset-*)`).
- Экран не должен гаснуть во время игры — опционально Screen Wake Lock API, где поддерживается.

### Локализация

- Два языка: русский (по умолчанию) и английский. Переключатель — на стартовом экране и во вкладке «Настройки»; выбор запоминается в `localStorage` отдельно от сессии.
- Все тексты — в `i18n.js` (словари `ru` и `en`), в коде интерфейса только ключи.
- Множественное число — через `Intl.PluralRules` (в русском три формы: «1 тур», «2 тура», «5 туров»).
- Текст «Поделиться итогами» формируется на текущем языке. Обозначение В-Н-П по-английски — W-D-L.

## Тесты

Готово, когда все проверки ниже проходят автоматическими тестами (`node --test`) для `scheduler.js` и `scoring.js` и вручную на телефоне.

### Проверки расписания

- [ ] Американо, 1 корт, 4 игрока: за 3 тура все 3 разбивки на пары встречаются по разу.
- [ ] Американо, 1 корт, 5, 6, 7, 8 игроков: в любой момент разница в числе матчей ≤ 1; через n / НОД(n, 4) туров у всех поровну.
- [ ] Американо, 1 корт, 8 игроков, 7 туров: повторов напарников нет.
- [ ] Американо, 2 корта, 8–12 игроков: разница в числе матчей ≤ 1; через n / НОД(n, 8) туров у всех поровну; никто не стоит на двух кортах одновременно.
- [ ] Подсказка «до равного числа игр» совпадает с фактом для 5–9 игроков на 1 корте и 9–12 на 2 кортах.
- [ ] Опоздавший игрок попадает в ближайший тур и играет подряд, пока не догонит; выбывший больше не появляется.
- [ ] Заранее показанный следующий тур совпадает со сыгранным, если состав не менялся.
- [ ] Пары по кругу, 1 корт, 3 пары: за 3 матча каждая сыграла с каждой; ни одна не играет 3 раза подряд при 4+ парах.
